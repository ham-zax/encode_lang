# Lambda H/2.1 field-and-graph specification

This is a forward extension of the V2 graph. It adds directional semantic fields and a numeric-only default wire while preserving exact relations, action targets, instruments, conditions, policy and task progress. It is not V1 restored, a cipher, a word dictionary, an execution engine, or access to a model's hidden representations.

## 1. Authoritative boundaries

`src/protocol.py` owns the developer graph and graph invariants. `src/wire.py` owns the numeric transport tables and its encode/decode boundary. `src/geometry.py` evaluates fields against supplied coordinates using that graph's field schema. `semantics/basis.json` owns the anchor meanings. `prompt/BOOTSTRAP.md` is the complete standalone receiver/encoder reference, including the tables and anchors.

The JSON Schema generated by `python3 -m src.codec schema` describes the **developer graph after numeric decoding**, not the raw wire array. Graph validation and wire exportability are distinct: explicit developer JSON may contain exact text, but normal wire emission rejects that text. No formatter may silently omit it or transform it into character codes.

## 2. Numeric wire

`ΛH2.1|` is followed by a JSON array of tagged records; every leaf is a finite number. Object keys, strings, raw booleans, null and arbitrary literals are absent. The version marker is not part of that recursive numeric constraint.

Records are arrays of `[tag,value]` pairs. The stable tables are `src.wire.RECORDS` and `src.wire.ENUMS`, reproduced in the bootstrap. Tags are structural field identities, never mappings from complete words to secret tokens. Duplicate tags, unknown tags, malformed pairs, wrong types, non-finite numbers and undeclared local references are rejected.

Root tags are 0 context, 1 mode, 2 E, 3 R, 4 A, 5 T, 6 C, 7 K, 8 P, 9 X, 10 V, 11 task, 12 control, 13 refs and 14 invalid-code. References are `[namespace,index]`, with namespace 0 entity, 1 relation, 2 action, 3 tool, 4 condition and 5 X. X indices 10..15 are reserved; other X indices lie in 0..255. Numeric indices must be nonnegative integers at most 9007199254740991.

Node IDs become canonical decimal indices. A developer context/task ID must be a canonical nonnegative decimal string to be wire-exportable; descriptive names or leading-zero aliases are rejected rather than silently renamed. A numerical namespace is not proof that a receiver knows its bindings, nor is it an authenticated identity.

A point q is an array of `[axis,coordinate]` pairs. A field f is a list of component records; component tags are 0 q, 1 s, 2 b and 3 w. Bands b are `[axis,[lower,upper]]` pairs. The parent node selects the semantic layer.

Typed nontext scalar forms are `[0,number]`, `[1,0-or-1]` and `[2]` for null. These allow actual quantities and boolean/null data without confusing them with references. They must not be used as a text-encoding escape. Enum indices are fixed by the bootstrap tables. Arrays preserve order; insignificant whitespace does not change meaning.

## 3. Developer graph and semantic fields

Developer JSON identifies `protocol` as `ΛH/2.1`. E/R/A/T nodes retain their IDs, references, optional u and existing exact data fields. They may carry **q or f, never both**. V remains a point representation for residual nuance. R and A require q or f; E and T can instead use exact data in a deliberately readable developer representation.

A point q is a nonempty sparse map of layer axes to signed integer coordinates in -7..7, omitting zero. Layer widths are E32, R16, A16, T16 and V8. Negative means meaningful opposition, not missing relevance or logical negation.

A field component requires q (center) and s (positive default width, no more than 14). Optional b maps axes to two positive widths `[lower,upper]`, each at most 14. Optional w is a positive relative peak weight at most 1; omitted w means 1. Unknown axes or invalid/non-finite widths are rejected. Multiple components preserve separate neighborhoods; they are not averaged into one center.

For a supplied coordinate vector x, let sigma on axis i be the lower width if x_i < q_i, the upper width otherwise, falling back to s. Each component contributes:

```text
k_j(x) = exp(-0.5 * sum_i ((x_i - q_ji) / sigma_ji)^2)
F(x)   = sum_j w_j * k_j(x) / sum_j w_j
```

Omitted point axes are zero. A single component has activation 1 at its center. Separated components may have lower scores at their individual centers because their contributions are normalized together. This is a Gaussian-shaped **compatibility field**, not a normalized probability density, physical light, a calibrated probability of a word, or a learned model embedding.

`focus_field` changes widths only; `shift_field` translates centers while preserving widths and component separation. Invalid resulting fields fail, not clamp. An acceptance threshold is a decision policy and does not move a focus or add evidence. `rank_candidates` requires supplied numerical candidates, a minimum score and a margin; it reports all scores and abstains on weak or tied results. No candidate lexicon is bundled.

Uncertainty u remains 0..7 and independent of widths. Narrowing a field does not establish epistemic certainty. A broad concept can be answered broadly without selecting one exact word; ask for a distinction only when the task depends on it.

## 4. Exact directed structure is retained

R has ordered subject and object references. A has its own target and optional tool reference, prerequisite list, when/until condition and prohibition. Argument order and hard flags do not become fuzzy because q is replaced by f. Prerequisite cycles are invalid. Without a task snapshot, independent actions follow declaration order after their prerequisites.

C supports eq, ne, lt, le, gt, ge, exists and done. Binary comparisons need both operands; exists and done take only left. Done references an action. Missing or ambiguous observations produce unknown, not false. A path string is not evidence that a resource exists. When gates an action; until and task stop are checked before more execution. The Python inspector does not evaluate external conditions.

K00..K08 retain observed, reported, assumed, hypothesized, inferred, multiply supported, contradicted, unknown and confirmed-to-required-standard states. Confidence is optional in 0..1; truth only qualifies a relation or condition. A declaration of truth/confirmation is not independent evidence.

P retains exact mutation/tools booleans, scope references, detail/reply selections and effort/initiative preferences. False is a prohibition; true only requests behavior within existing authority. Omission inherits established limits. Optional decoder arithmetic is permitted unless tools are explicitly forbidden. Scope cannot enlarge prior authorization. For protocol replies the bootstrap prefers numeric packets; explicit natural output remains supported.

Task snapshots retain id, revision, state, goal, ordered steps and done; active snapshots require the first unfinished step as next. Complete accounts for all steps with no next. Blocked requires a blocker and no next; cancelled has no next. Completed dependencies must be completed before their dependents. Reconcile stale/conflicting snapshots against actual evidence. No persistence, exactly-once effects or background work is supplied by the codec.

## 5. Context and handoffs

Only scoped X references can use external context. Reserved roles X00..X09 are subject, previous subject, goal, artifact, hypothesis, result, plan, blocker, environment and output. A role name does not establish its binding. X10..XFF are explicitly supplied dynamic bindings.

Exact textual identities remain outside normal wire. An already shared X binding can supply an exact filename or quotation; absent identity must be requested rather than reconstructed from a vague region. Do not replace this boundary with byte encodings, hidden word dictionaries or invented identity recovery.

`inspect_packet` checks required/missing IDs and namespace conflicts without printing binding values. The Python `make_handoff` helper returns an explicit **developer** graph with only referenced X bindings. It is not opaque wire.

The CLI `handoff --output NEW_DIRECTORY` validates the entire export before creating the directory, then writes `packet.lh` and `context.private.json` separately. The packet no longer claims inline handoff mode. The sidecar contains selected exact bindings and is readable disclosure; transfer it only deliberately. The destination must be new, and the parent must exist. No existing file is overwritten. An I/O failure may leave a partial new directory; no atomic-transfer claim is made.

Inline bind/handoff modes remain available for nontext scalar bindings. A fresh receiver of a packet without its required sidecar must request context. Neither numeric IDs nor selection of fewer bindings provides cryptographic confidentiality.

## 6. Controls and behavioral evidence

```text
ΛH2.1|[[12,0]]
ΛH2.1|[[0,7],[12,1],[13,[[5,3]]]]
ΛH2.1|[[12,2],[14,0]]
```

These are ready, need X03 in namespace 7, and invalid-shape respectively. Controls contain no task payload. Invalid codes are 0 shape, 1 local reference, 2 context conflict and 3 inconsistent state. A targeted ordinary question may resolve material semantic uncertainty; do not leak unrelated context through diagnostics.

A bootstrap plus a task should act on the task immediately. A bare packet should not trigger a compulsory English reconstruction or routine acknowledgement. Python usage is allowed, not proof of failure. Actual task tools still need their ordinary permissions.

The calibration recorder binds observations to the exact bootstrap and corpus. Mechanical geometric checks, valid packets, a READY response and old V2 receiving results are not new receiving-model evidence. No claim is made that this protocol controls a model's hidden reasoning language or bypasses a provider's safeguards.
